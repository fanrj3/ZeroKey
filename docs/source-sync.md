# 来源模型同步

在 ZeroKey → 模型来源，按来源点击「同步模型」，查看新增型号与上游未返回的旧型号。选择后点击「确认添加」。新增路由随后出现在项目授权和 MCP 模型目录中，项目仍按原有的单项目、本机确认流程申请访问。

目前支持现有的 BBAI、Openlux、OpenCode Go 和 OpenCode 余额付费适配。来源需先在 LiteLLM 配置至少一个模型及对应服务器环境变量；其他来源继续在「管理来源」中维护。Openlux 延用可识别文字型号筛选，Go 与余额付费保持独立路由，目录发现不代表调用验证通过。

每个来源的「自动添加」默认关闭。开启后，原生后台在启动后检查一次，并在托盘运行期间每 6 小时检查。较大批次分批补齐。来源记录按网关分别存放于本机数据目录，保留最近 10 次结果。

最近一次成功同步未返回的已接入型号标为「不可获取」，从桌面、CLI、MCP 的可选目录和新授权中排除；已有项目通过 ZeroKey 启动时也无法选择这些型号。后续成功同步重新返回时自动恢复可选。成功返回合法空目录表示该来源当前没有可获取型号；网络失败、HTTP 错误或格式异常沿用上次成功同步的判断。项目的全部模型均不可获取时，项目显示「模型不可获取」，Agent 状态返回 `unavailable`。网关已有路由与项目凭证保留，不自动删除或撤销；此目录规则不会修改 LiteLLM 中已签发凭证的权限。

原始来源 Key 留在 LiteLLM 服务器。Rust 后台使用管理接口注册固定、需鉴权且仅允许 GET 的目录透传路由，再比较 `/model/info` 并通过 `/model/new` 添加缺失路由。来源环境引用分别为 `BBAI_API_KEY`、`OPENLUX_API_KEY` 和 `OPENCODE_API_KEY`；没有把 `.env` 或凭证文件打包到桌面应用。网关无需重启。固定目录透传可在 LiteLLM 的透传管理中查看。

目录查询有 30 秒的短期缓存和请求间隔。确认添加使用 10 分钟内的审核快照，并重新核对网关已有路由；过期预览需要重新检查目录。重复添加会跳过，部分失败会保留已添加结果和剩余选择。来源同步使用独立的操作锁，不占用项目授权锁；更新安装会等待同步操作结束。

桌面和后台自动任务共用 Rust 的同步实现。排障时可以使用原生操作员入口，输出只含非敏感目录状态：

```powershell
# 工作目录可独立于源码
$zeroKey = Join-Path $env:LOCALAPPDATA 'ZeroKey/zerokey.exe'
& $zeroKey --broker source-status '{}'
& $zeroKey --broker source-check '{"source":"bbai"}'
& $zeroKey --broker source-apply '{"source":"bbai","models":["bbai/gpt-6.2-sol"]}'
```

这些来源管理操作不暴露为项目 MCP 工具。旧的 `scripts/sync-sources.ts` 继续用于开发期批量导入和凭据迁移；安装版的同步不依赖该脚本或开发机目录。
